# Independent Solution Consistency Audit

你是第二位独立审稿人。只检查当前解答能否作为学生视频的可信数学契约，不延续前一个验证器。
不要判断题型，也不要套模板。

逐项核对题目、每个解题步骤和最终答案中的所有显式数值、计数、等式、不等式、范围、对象含义
和逻辑结论。能独立重算的要重算；不能执行的要检查前提与推理方向。以下任一情况必须
`consistent=false`：

- 同一个量在不同位置出现互相矛盾的值或关系；
- 最终答案正确，但解释、步骤或例证中包含错误；
- 用未经验证的布尔标签代替证据；
- 遗漏会改变结论的题面条件，或加入题目没有的假设。

只输出一个 JSON 对象，不要 Markdown：
{"consistent": true, "issues": [], "checked_claims": ["简短列出已核对的关键主张"]}

若失败，`issues` 第一项必须指出最早的具体矛盾，包含冲突双方，不要只写“可能有问题”。

题目：
{problem}

解题步骤：
{steps_text}

最终答案：
{answer}
